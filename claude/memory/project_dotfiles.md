This is a personal macOS dotfiles repo managed by Martin Chen.

**Shell:** zsh with Starship prompt (customized catppuccin-powerline layout, Dracula palette), zsh-autosuggestions, zsh-syntax-highlighting. No Oh My Zsh — plugins sourced directly via Homebrew.

**Prompt:** Starship (`starship/starship.toml`) is a customized catppuccin-powerline layout: OS icon → username → full directory → git branch/status on the left, `❯` on a second line; cmd_duration (with notifications over 45s) and language versions on the right. Active palette `dracula`; other palettes (Catppuccin Mocha, TokyoNight Storm, Everforest Dark, Catppuccin Frappé/Latte/Macchiato, Kanagawa Dragon/Wave, Rose Pine/Moon) use the same Catppuccin key names and are toggled by the `palette =` line. Nerd Font characters (edges, icons) were missing for a long time and were restored 2026-11-09; if edges look flat again, check the file still contains private-use glyphs. Stock presets (gruvbox-rainbow, catppuccin-powerline) and a minimal Pure-style prompt were tried that day and rejected; the user prefers this powerline look.

**Terminal:** Ghostty with MapleMono NF CN font, Dracula theme (switched 2026-11-17 from Catppuccin Mocha, which had been chosen 2026-11-14 as the final theme; the other themes, Catppuccin Mocha included, are left commented out in each app), `copy-on-select = clipboard`, `shell-integration = zsh`, `shell-integration-features = no-title` (tab titles managed manually via zsh precmd).

**Package management:** Homebrew via `brew/Brewfile` (common) + machine-specific `~/.Brewfile.personal` or `~/.Brewfile.work`. Key brews: fd, fzf, gh, starship, jq, lazygit, node, ripgrep, tmux, yazi, zoxide, zsh-autosuggestions, zsh-syntax-highlighting. Casks: `font-maple-mono-nf-cn`, `maccy` (clipboard manager), `shottr` (screenshot tool). Work-specific adds: awscli, telnet, tmate, cloudflared, helm, k3d, etc.

**Multiplexer:** tmux (replaced zellij). Config at `tmux/.tmux.conf` → `~/.tmux.conf`. Includes mouse support, 10k scrollback, `Prefix+L` to toggle pipe-pane logging to `/tmp/tmux-YYYYMMDD.log`.

**Claude Code:** `claude/statusline.sh` symlinked to `~/.claude/statusline.sh`. Requires manual addition of `statusLine` config to `~/.claude/settings.json` (see README).

**Setup script:** `setup.sh` — runs Brewfiles, installs global npm packages, and symlinks all configs (zsh, git, starship, ghostty, vscode, cursor, claude statusline). VS Code custom icon: `vscode/apply-icon.sh` is made executable but NOT auto-applied or installed as a launchd agent (removed because it broke VS Code's code signature on updates). Run manually after VS Code updates.

**Machine-specific overrides:** `~/.zshrc.personal` and `~/.zshrc.work` sourced at end of `.zshrc`. Brewfiles follow the same pattern.

**History:** `INC_APPEND_HISTORY` (append immediately), `SHARE_HISTORY` disabled (no cross-session sharing).

**Why:** Clean separation of personal vs. work config; Starship was re-added after a revert (commit history shows Starship → revert → re-add with full Catppuccin config).
**How to apply:** When suggesting prompt/shell changes, work within the customized Starship layout + Dracula aesthetic. Dracula is set in every app (bat uses its built-in Dracula theme; btop TTY follows Ghostty; Slack is themed by hand in its own preferences; the Claude desktop app (Settings → Appearance) has no Kanagawa code theme and uses Vitesse Dark/Vitesse Light, chosen 2026-11-12 as the closest match to Kanagawa Dragon, with the System interface font (not Anthropic Sans) and MapleMono NF CN as the code font). Commented-out alternative themes exist in Ghostty, fzf, Zellij, VS Code/Cursor and Sublime; switching means toggling one line per app. Machine-specific config goes in `~/.zshrc.personal` or `~/.zshrc.work`, not in the dotfiles repo itself.

**Current theme (2026-11-26):** Catppuccin Mocha is active everywhere again (Ghostty, Starship, bat `Catppuccin Mocha`, fzf, VS Code/Cursor, Sublime, Zellij built-in, lazygit, Claude mod `catppuccin-mocha`, Codex dark code theme `catppuccin` + Mocha chrome in `~/.codex/config.toml` / `codex/themes/catppuccin-mocha.txt`, Slack via catppuccin/slack Mocha string). **Previous (2026-11-24):** Tokyo Night Storm was active everywhere (Ghostty, Starship, bat `ansi`, fzf, VS Code/Cursor `enkia.tokyo-night`, Sublime, Zellij custom block, lazygit, Claude mod `tokyo-night-storm`, Codex). Path that day: Kanagawa Dragon → Everforest Dark (too muted at Medium; needed Hard + `everforest.highContrast`) → Gruvbox Dark → Tokyo Night Storm. **User's top 3: Catppuccin Mocha, Tokyo Night Storm, Kanagawa Dragon.** Also keep on the candidate list: Dracula and Gruvbox Dark. Everforest felt a little too low-contrast for the user — don't suggest it as a pick (its configs are still in the repo, commented out). Icon theme: Seti (`vs-seti`, built in) in VS Code and Cursor. Slack: use folke's official `extras/slack/tokyonight_storm.txt` (`#1d202f,#292e42,#bb9af7,#2e3c64`). Claude mods now also include `everforest-dark`, `gruvbox-dark`, `tokyo-night-storm`; new mods are built by copying an existing mod and swapping `colors.ts`, then iterating until `claude plugin test` passes (light ramp must run darkest→lightest with surface-2 == surface-3; darken dark surfaces when text-muted fails). Codex app themes are `codex-theme-v1:<JSON>` strings imported via Appearance → import, kept in `codex/themes/` (codeThemeId must be a Codex built-in; `tokyo-night` is the Night variant only). Gotchas: `code` on PATH is Cursor's CLI, so install VS Code extensions with the VS Code app's own binary; `~/.claude/settings.json` is a copy, so run `bash claude/sync.sh` after editing the repo copy, then fully quit and reopen the Claude app; Sublime color schemes each need a symlink line in `setup.sh`.

**Theme preferences (2026-11-12):** Candidate set (trimmed 2026-11-12): Catppuccin, TokyoNight (Storm), Kanagawa (Wave, Dragon), Rose Pine (base, Moon) and Everforest (Dark). The user wants theme families with both dark and light variants, so Dracula (no light variant) and Ayu Mirage were removed that day (Dracula was brought back as the active theme on 2026-11-17, with Alucard as its light variant); Solarized Dark felt too low-contrast and Selenized Dark was dropped. Nord and Gruvbox were tried on 2026-11-10 and removed, and other themes were removed earlier. Catppuccin Mocha and Rose Pine are favorites; within Rose Pine, Moon is slightly preferred over the base variant. Dracula felt a bit too high-contrast, and Rose Pine later felt a little too purple; lean toward softer palettes that are not strongly purple. Icon themes: VS Code and Cursor use Catppuccin Icons (`catppuccin-mocha`) with Catppuccin Mocha; Symbols (miguelsolorio.symbols) is the muted match for Kanagawa, and VS Code uses it with Dracula (2026-11-17). The user wants minimal icons (Material Icon Theme is too busy).

**Claude app theme (2026-11-14; corrected 2026-11-18):** The app's Settings → Appearance exposes a native **Code syntax-theme** picker only (two dropdowns: one light-mode, one dark-mode code theme). Its options (from the bundle `{value,label,mode}` list) are: ayu-dark, catppuccin-latte/mocha, dracula(+soft), github-dark/dimmed/high-contrast/light, min-dark/light, monokai, night-owl, nord, one-dark-pro, one-light, pierre-dark/light, rose-pine(+dawn), slack-dark/ochin, solarized-dark/light, tokyo-night, vitesse-dark/light, vscode-dark/light. **Kanagawa is NOT in this picker** (kanagawa-dragon/wave/lotus ship as bundled highlighter themes but aren't exposed). The **whole-app chrome palette is NOT natively themeable** — it only follows system light/dark unless a **mod** sets it. So earlier "native color themes make mods redundant" was WRONG: native = code syntax only; whole-app look still needs a mod. A mod sets BOTH the chrome colors and the code theme, and while enabled it overrides the native Code dropdowns (Appearance shows "A mod set the colors and the code theme… turn off the mod"). Mods live in `claude/mods/` from a local marketplace named `dotfiles` (user scope, read straight from the folder; `/reload-plugins` picks up edits): `dracula` (Dracula dark, Alucard light), `catppuccin-mocha` (Mocha dark, Latte light), and `kanagawa-dragon` (added 2026-11-18). Installing or enabling plugins is blocked by the auto-mode classifier, so give the user the `claude plugin` commands to run. A purple tint in the app's sidebar came from macOS wallpaper tinting, not the theme.

**Color perception (2026-11-15):** When Catppuccin looks "off" (e.g. yellow less white, red less pink than remembered), the config is not the cause: screenshots confirmed the exact palette values. The cause was the built-in display's macOS color profile being set to sRGB IEC61966-2.1 (colors oversaturated on the P3 panel); the user switched it to Display P3 on 2026-11-15. External monitors, Night Shift and True Tone can shift colors the same way and don't show in screenshots. Don't tweak theme colors for this.
